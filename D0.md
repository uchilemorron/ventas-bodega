# D0 — Documento Base de Requisitos

**Sistema:** Sistema web interno para el minimarket «La Esquina»
**Negocio:** Minimarket «La Esquina», San Vicente de Cañete
**Fecha:** 23 de octubre de 2026

---

## 1. El problema

El minimarket no controla sus ventas ni su stock de forma confiable porque ambos se llevan en un cuaderno y a ojo, por lo que el dueño desconoce cuánto vendió al cerrar el día y se queda sin productos de alta rotación sin advertirlo.

---

## 2. Usuarios del sistema

| Usuario | Qué hace en el sistema |
|---------|------------------------|
| **Cajero** | Registra los productos nuevos cuando llega mercadería (código, nombre, categoría, precio de venta, stock actual y stock mínimo). Lista los productos para revisar el stock y ver cuáles están en su nivel mínimo o por debajo. Registra las ventas del día: escoge el producto, indica la cantidad y el sistema calcula el total, descuenta el stock y guarda la fecha y hora. Al cerrar el día consulta la lista de ventas y el total vendido. |
| **Dueño** | Revisa la lista de productos para ver cuáles están agotándose o por debajo del mínimo. Consulta las ventas del día y el total vendido para saber cómo va el negocio. No opera la caja directamente. |

> **Nota:** El sistema no tiene inicio de sesión ni roles (ver sección 7). Cualquiera que entre a la página puede hacer lo del cajero. La distinción entre cajero y dueño es solo para entender quién usa cada parte.

---

## 3. Proceso actual, dificultades y consecuencias

### Cómo trabajan hoy

Hoy el cajero anota cada venta en un cuaderno: escribe el producto, la cantidad y el precio. El stock se controla caminando por el local y mirando los estantes para ver qué falta. Al cerrar el día, el dueño revisa el cuaderno a mano si quiere saber cuánto vendió, pero muchas veces no lo hace porque es lento y poco práctico.

### Dificultades del proceso actual

- **Las ventas se anotan a mano** y es fácil equivocarse en la cantidad, el precio o saltarse una venta.
- **El stock se controla a ojo** mirando los estantes, sin un número confiable de unidades disponibles.
- **No hay un total del día automático**: el dueño tiene que sumar a mano las ventas del cuaderno, lo cual tarda y da errores.
- **No hay alerta de stock mínimo**: nadie se entera de que un producto está por agotarse hasta que ya no queda en el estante.

### Consecuencias para el negocio

- El dueño **no sabe cuánto vendió** al cerrar el día, lo que dificulta saber si el día fue bueno o malo y tomar decisiones.
- **Se queda sin productos de alta rotación** sin darse cuenta, perdiendo ventas porque los clientes no encuentran lo que buscan.
- **No hay un registro confiable** de lo que entra y sale, por lo que no se puede detectar pérdidas ni faltantes.
- El tiempo que el dueño o cajero gastan sumando y revisando el cuaderno **se podría usar en atender mejor**.

## 4. Requisitos funcionales

| ID  | Nombre | Descripción |
|-----|--------|-------------|
| **RF1** | Registrar productos | El cajero registra un producto con los datos: código, nombre, categoría, precio de venta, stock actual y stock mínimo. El código no puede repetirse y el precio de venta no puede ser negativo. |
| **RF2** | Listar productos | El sistema muestra todos los productos registrados y destaca los que están en su stock mínimo o por debajo del mínimo, para que el cajero y el dueño sepan qué hay que reponer pronto. |
| **RF3** | Registrar venta | El cajero escoge un producto y una cantidad. El sistema usa el precio de venta vigente del producto, calcula el total (precio × cantidad), guarda la fecha y hora de la venta y descuenta la cantidad vendida del stock. La venta y el descuento del stock se hacen juntos o no se hace ninguna de las dos. No se puede vender más de lo que hay en stock ni una cantidad menor o igual a cero. |
| **RF4** | Listar ventas del día | El sistema muestra todas las ventas registradas en la fecha actual (desde las 00:00 hasta las 23:59) con el producto, la cantidad, el precio, el total y la fecha y hora de cada venta, junto con un total general vendido en el día. |

## 5. Requisitos no funcionales

Los requisitos no funcionales se centran en la seguridad y la integridad de los datos, porque el sistema maneja dinero y stock, y un error o manipulación puede causar pérdidas al negocio.

| ID   | Categoría | Descripción |
|------|-----------|-------------|
| **RNF1** | Tecnología | El sistema se desarrolla en **PHP 8 orientado a objetos**, usando clases, encapsulamiento y separación de responsabilidades para que el código sea mantenible y ordenado. |
| **RNF2** | Base de datos | Los datos se guardan en una base de datos **MySQL**. Las tablas de productos y ventas deben estar bien definidas con sus tipos de datos y relaciones correctas. |
| **RNF3** | Integridad de datos | Toda consulta a la base de datos se hace con **PDO y sentencias preparadas** para evitar inyección SQL, es decir, que nadie pueda manipular las consultas enviando datos maliciosos por los formularios. |
| **RNF4** | Seguridad | Todos los formularios incluyen un **token CSRF**, un valor oculto que el servidor verifica al recibir el formulario, para evitar que alguien envíe datos falsos desde otra página. |
| **RNF5** | Seguridad | Toda la información que se muestra en la página (nombres de productos, cantidades, precios, etc.) se imprime con **`htmlspecialchars`** para evitar que se ejecute código malicioso en el navegador. |
| **RNF6** | Seguridad | Las credenciales de la base de datos (usuario, contraseña, nombre de la base, host) se guardan en un **archivo `.env`** que no se versiona en el repositorio, para que nadie con acceso al código pueda verlas. |
| **RNF7** | Integridad de datos | El registro de una venta y el descuento del stock se ejecutan dentro de una **transacción** en la base de datos: si alguna operación falla, todo se revierte y queda como si la venta nunca hubiera ocurrido. |
| **RNF8** | Manejo de errores | Los errores de base de datos se capturan con **excepciones propias**, se registran internamente y al usuario solo se le muestra un mensaje claro, nunca trazas ni detalles técnicos. |

## 6. Reglas de negocio

| ID  | Regla | Descripción | Afecta a |
|-----|-------|-------------|----------|
| **RN1** | La cantidad vendida debe ser mayor que cero | Al registrar una venta, la cantidad ingresada tiene que ser un número positivo (mayor que cero). No se permiten cantidades en cero o negativas. | RF3 |
| **RN2** | No se puede vender más de lo disponible en stock | Al registrar una venta, el sistema verifica que la cantidad solicitada no sea mayor al stock actual del producto. Si lo es, no se permite la venta. | RF3 |
| **RN3** | El precio de venta no puede ser negativo | Al registrar un producto, el precio de venta debe ser un valor mayor o igual a cero. No se permiten precios negativos. | RF1 |
| **RN4** | El código del producto no se puede repetir | Al registrar un producto, el sistema verifica que el código no exista ya en la base de datos. Si existe, no se permite el registro. | RF1 |
| **RN5** | La venta y el descuento del stock van juntos | El registro de la venta y el descuento del stock se realizan en la misma operación. Si el descuento del stock falla, la venta no se registra. Si la venta no se registra, el stock no se descuenta. Ninguna de las dos puede ocurrir sin la otra. | RF3 |

## 7. Fuera de alcance

El sistema no incluye lo siguiente, porque el contexto del negocio no lo requiere en esta etapa:

- **Inicio de sesión:** no hay autenticación de usuarios. No hay usuario ni contraseña para entrar al sistema.
- **Roles de usuario:** no hay distinción de permisos entre cajero y dueño a nivel del sistema. La separación es solo descriptiva en este documento.
- **Gestión de clientes:** no se registran datos de los clientes ni se lleva un historial por cliente.
- **Boletas o facturación electrónica:** no se emiten documentos fiscales ni se envían a SUNAT.
- **Agentes conversacionales:** no hay chatbot ni asistente de voz.
- **Despliegue público:** el sistema se ejecuta en una red interna del local, no está abierto a internet.

## 8. Supuestos

- SUPUESTO: solo un cajero usa el sistema por turno.
- SUPUESTO: los precios se manejan en soles (S/) e incluyen IGV.
- SUPUESTO: cada venta corresponde a un único producto.
- SUPUESTO: el cajero registra los productos nuevos cuando llega mercadería.
- SUPUESTO: las ventas del día se cuentan desde las 00:00 hasta las 23:59 de la fecha actual.
